# Project state

Date: 2026-09-13. Executable code and checked results take precedence over this document.

The initial repository was README-only at `18d5058`. ESTIMATOR now implements the supplied Calculator in a local browser interface, backed by explicit Python calculations and SQLite. The immutable initial data contains 417 inventory records and 166 choices across 14 groups. The application exposes the 64 Calculator inputs and 151 translated formulas. Microsoft Excel and the original workbooks are not required at runtime.

The current pricing-library extension adds Export Excel and Import Excel. Export contains the complete effective draft in Inventory, Rates and Instructions sheets. Import proposes a full replacement, including added/removed products, rate choices and updated prices; the active library changes only after review and Save pricing. Existing IDs preserve identity, while new rows can receive new IDs. Rates distinguish inventory-linked prices from explicit overrides. Unsupported categories, broken links, duplicate choice names and invalid values are rejected.

The exchange format is values-only `.xlsx`, using the exported headers and supported groups. It accepts at most 5 MB and 5,000 rows per list, with bounded archive contents; formulas, macros, external links and unexpected data sheets are rejected. Hidden or filtered rows are still imported. It does not infer arbitrary supplier spreadsheet layouts. Original baseline JSON stays unchanged; the current catalog and separate edits use the existing configuration JSON in SQLite.

Saved quotes now embed their catalog and effective rate/yield values, alongside input and result snapshots. A library replacement does not rewrite saved products, prices or PDF results. Older records without a catalog continue to use the original baseline and identity guard. Use current pricing explicitly adopts the new library and exposes removed selections as errors to resolve. There is no database schema migration or automatic quote rewrite.

The estimator and PDF now use named business fields and error descriptions instead of redundant worksheet cell addresses. Internal source mappings, formula evaluation, stored calculation evidence and regression fixtures remain intact. The supplied official logo and complete material/labour breakdown remain part of PDF reporting. Unchanged saved reports render their stored results; edited/new reports render captured inputs and pricing without saving.

Runtime dependencies are ReportLab 4.4.9 for PDF generation and openpyxl 3.1.5 for pricing workbook exchange. The Windows double-click launcher checks every package pinned in `requirements.txt`. It starts or reuses a local background server; it does not install packages or create automatic startup. Reopen the launcher after a Windows restart. The localhost URL is a running local application, not a hosted service.

Validation on `feat/pricing-workbook-library`: all 77 Python tests passed with both original-workbook checks enabled, along with eight UI transition checks and JavaScript syntax validation. The independent spreadsheet editor round trip preserved all original prices and added a test product correctly. Browser review confirmed draft-only import, Save, the new dropdown choice and its calculated amount. All five pages of the revised PDF sample were visually checked. The source distribution, extracted import/export/calculation/PDF smoke test and Windows PowerShell 5.1 startup passed. Refreshing the live application preserved its saved quote and settings checksum. See the pull request for publication, CI and merge status; local success is separate evidence.

The unchanged parity fixture covers 216 independent Microsoft Excel scenarios, with 151 formula outputs per scenario. The original XLSM could not be opened by Excel automation, so exact formulas were recalculated in an isolated macro-free harness with frozen source lookups. See `CALCULATOR_SPEC.md` for this evidence boundary. The original XLSM files have not been changed by this implementation.

Workflows use user-entered quantities and coverage as Excel does. They do not derive quantities from dimensions or FRL; the source templates contain no such formulas. No technical suitability rules have been invented. The local application is not an authenticated multi-user or production-hosted deployment.
